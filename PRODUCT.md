# OCABC Challenge

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated by the user: React, TypeScript and Vite, with a standalone HTML build that opens directly from the desktop. No backend is needed for this first UI demo.

## Users

Banking customers who receive a suspicious request and need a calm, understandable way to verify it before transferring money or disclosing sensitive information.

## Product Purpose

Demonstrate a useful moment of friction: review a request, verify through an existing independent channel, then pause or finish a simulated transfer review.

## Operating Context

Desktop-delivered demo and a public GitHub repository named OCABC-Challenge. Mobile-first responsive web is the implementation assumption. Simplified Chinese is the initial interface language. The user delegated software and UI implementation decisions.

## Capabilities and Constraints

Local, deterministic message-risk explanations; guided verification; simulated transfer checks; immediate-help guidance and a locally downloaded incident note. No real transfers, bank integration, identity verification, AI detector, OCR, login, or server uploads. No risk score or claim of proven safety. Sample scenarios are fictional. Unsaved input lives in memory only.

## Brand Commitments

Familiar, trustworthy, minimal banking-service appearance, readable in every state. No emoji, gradients, glass, shadows, Lucide icons, rounded card grids, testimonials, pricing sections, neon, decorative motion, or irrelevant page content. Do not copy the official OCBC logo or imply the demo is a bank service.

## Evidence on Hand

User brief: PS3 Digital Trust, and three anti-pattern reference screenshots. Official OCBC security guidance and Singapore Government Design System content/accessibility references were consulted. The screenshots are references only and must not be published in the repository.

## Product Principles

- Turn a warning into one concrete next action.
- Separate content clues from identity verification.
- Use independent contact channels, never those supplied by the suspicious request.
- Make pausing easier than rushing.
- State the demo boundary without crowding the main task.
